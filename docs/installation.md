# Zapi Social installation guide

This guide installs Zapi Social with Docker Compose. It creates PostgreSQL,
Redis, API, Worker, and Web containers, applies every database migration, and
keeps database, Redis, and uploaded files in persistent volumes.

## 1. Requirements

- A Linux server with a current Docker Engine and Docker Compose v2.
- Recommended minimum: 4 CPU cores, 8 GB RAM, and 20 GB free disk space.
- Two DNS names with HTTPS, one for Web and one for API. For example,
  `app.example.com` and `api.example.com`.
- A reverse proxy such as Caddy, Traefik, or Nginx.
- Outbound HTTPS access for social networks, billing, and optional media
  providers.

Shared hosting without Docker is not supported.

## 2. Prepare the configuration

Extract the release archive, enter its directory, and create the local
configuration file:

```bash
cp .env.example .env
chmod 600 .env
```

Generate different random values for PostgreSQL, Redis, and JWT:

```bash
openssl rand -hex 32
```

The provider-integration encryption key has a stricter format. Generate it as
exactly 32 random bytes encoded in canonical Base64:

```bash
openssl rand -base64 32
```

Edit `.env` and replace every `CHANGE_ME` value. For a public installation,
also set:

```dotenv
WEB_ORIGIN=https://app.example.com
API_PUBLIC_ORIGIN=https://api.example.com
COOKIE_SECURE=true
# COOKIE_DOMAIN=.example.com
```

`WEB_ORIGIN` and `API_PUBLIC_ORIGIN` must be exact origins: scheme and host,
without a trailing path. Use hexadecimal secrets for PostgreSQL and Redis so
their values are safe inside the generated database URL. Set
`PROVIDER_INTEGRATIONS_ENCRYPTION_KEY` only to the Base64 value generated by
the second command; a hexadecimal value is not accepted for that setting.

Never send `.env` to support, commit it to source control, or include it in a
backup shared with another person.

## 3. Validate and start the stack

Validate the resolved configuration before building:

```bash
docker compose config --quiet
```

Build and start every service:

```bash
docker compose build --pull
docker compose up -d
```

The `migrate` service waits for PostgreSQL and Redis, applies the Drizzle
migration history, and must finish successfully before API and Worker start.
Check it with:

```bash
docker compose ps
docker compose logs migrate
```

Expected state:

- `postgres`, `redis`, `api`, `worker`, and `web` are running and healthy.
- `migrate` exited with status `0`.

Do not continue if `migrate` failed. Inspect its logs and correct the
configuration first.

## 4. Complete the one-time setup

Open the Web URL in a browser. A new empty installation redirects `/login` to
`/setup`. Enter the primary administrator's name, email, and a strong
password. The setup operation can succeed only once and creates:

- the dedicated Platform Admin account, without a Portal workspace;
- an editable free starter plan for new registrations;
- an editable paid growth plan with higher limits.

After setup, the browser signs in and opens Admin. To create a Portal workspace
owner, sign out or use a private browser window and register a separate email
at `/register`. Platform Admin and Portal users must never share an account.

If setup reports that users exist but no Platform Admin is available, stop and
inspect the database history. The public setup route intentionally refuses to
take over a non-empty installation. Use the CLI bootstrap only during a
controlled recovery of a database you own; never expose temporary passwords in
shell history or support messages.

## 5. Configure HTTPS and the reverse proxy

Route the public hosts to these local ports:

| Public host       | Local target     |
| ----------------- | ---------------- |
| `app.example.com` | `127.0.0.1:3000` |
| `api.example.com` | `127.0.0.1:3001` |

Issue valid TLS certificates and redirect HTTP to HTTPS. Do not expose
PostgreSQL (`5432`) or Redis (`6379`) to the public network; the supplied
Compose file does not publish those ports.

After the proxy is ready, verify:

```bash
curl --fail https://api.example.com/v1/health
curl --fail --head https://app.example.com/login
```

The API response must report `status`, `database`, and `redis` as `ok`.

## 6. Finish application setup

1. Sign in to Web with the Platform Admin account.
2. Review Admin settings, languages, plans, email, billing, CAPTCHA, and
   provider integrations.
3. Configure provider callback URLs exactly as displayed by Admin. Those URLs
   are derived from `API_PUBLIC_ORIGIN`.
4. Sign in with the workspace owner and verify Portal access.
5. Send a test email and test each external provider before enabling it.

Provider credentials are stored through Admin, not in `.env`. Never use live
customer credentials while testing an installation.

## 7. Backups

Create a PostgreSQL backup:

```bash
mkdir -p backups
docker compose exec -T postgres sh -c \
  'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  > "backups/database-$(date +%Y%m%d-%H%M%S).sql"
```

Back up uploaded files:

```bash
docker compose exec -T api \
  tar -C /app/.data -czf - files \
  > "backups/files-$(date +%Y%m%d-%H%M%S).tar.gz"
```

Store backups encrypted and outside the application server. Test restoration
regularly. Redis contains queues and transient state; PostgreSQL and uploaded
files are the primary durable data.

## Troubleshooting

### A container does not become healthy

```bash
docker compose ps
docker compose logs --tail=200 postgres redis migrate api worker web
```

Check for an unchanged `CHANGE_ME` value, mismatched origins, occupied ports,
or insufficient memory.

### Login works locally but not through HTTPS

Confirm `WEB_ORIGIN`, `API_PUBLIC_ORIGIN`, and `COOKIE_SECURE=true`, then
recreate API and Web:

```bash
docker compose up -d --force-recreate api web
```

### OAuth callback is rejected

The callback registered at the provider must exactly match the callback shown
in Admin. Verify DNS, HTTPS, and `API_PUBLIC_ORIGIN` before reconnecting.

### Uploaded files disappear

Confirm that both API and Worker mount the same `files-data` volume. Never run
`docker compose down --volumes` unless you intentionally want to delete all
local application data.

For upgrades, follow [updating.md](./updating.md).
